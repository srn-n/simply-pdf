# Simply PDF Web 1.0.0

- Date: 2026-11-14
- Previous version: none (first web release)

## Earlier releases (one line each, newest first)

- None. This is the first web release. It's built from the Android app's code at Simply PDF 1.0.0 (`srn-n/Simply-PDF`, commit `e5adcf9`).

## What changed and why

Starting from the Android app's web code:

- **Android parts removed:** Capacitor, the `android/` project, the Play Store assets, the device tests and the signing setup. None of them apply in a browser.
- **Saving:** results download straight from a local `blob:`, in place of writing to Documents. Share uses the Web Share API where the browser has it (phones, Safari, Edge); elsewhere the Share button is hidden and Save does the job.
- **Offline (PWA):**
  - A service worker is built at deploy time. It precaches about 4.5 MB: the app and pdf.js's standard fonts. The CJK maps and scanned-image decoders are cached on first use.
  - Simply PDF opens and works with no connection after one visit.
  - It's installable from Chrome, Edge and Safari via `manifest.webmanifest` and new install icons.
- **Strict security for the open web:**
  - `csp.config.ts` is the single policy: `'self'` only, no inline scripts or styles.
  - `vercel.json` sends it as a header, along with nosniff, frame blocking, HSTS, no-referrer and a Permissions-Policy that turns off camera, mic, location and more.
  - `scripts/check-csp-build.mjs` fails the build if the page, `vercel.json` and the output drift apart.
  - The two inline-style fallbacks (the old-browser message and the crash message) now use a stylesheet class.
- **Honest copy for the web:** the Privacy page, the four promises, the FAQs, Settings › About and the launch screen talk about "this browser" and "this device", not "this phone" or Android permissions. The launch screen plays once per tab.
- **Web metadata:** a page title and description for search engines, Open Graph and Twitter preview tags, a 1200×630 `og-image.png`, an Apple touch icon and a maskable icon.
- **Tests:**
  - The Android manifest tests are replaced with CSP, header-parity and service-worker tests.
  - New smoke checks: offline use (a full merge with the network off, opened from a deep link), the install manifest and icons, and desktop layout at 1440×900.
  - The test that draws a sample photo now does it on `about:blank`; the app's own policy correctly blocked it on an app page.
  - The "Back is instant" check now ignores the tab bar's intended slide-back transition, which made it timing-dependent.

## Does the Android app need this too?

Two small things are worth porting later, but neither is urgent:
- The "Back is instant" smoke check's latent timing flake: the CSSAnimation-only filter in `scripts/smoke.mjs`.
- The stylesheet-class fallback messages, which make the app ready for a stricter policy.

Nothing else here applies to Android.

## Privacy policy: add this to the studio site

The current Simply PDF section at https://www.simplymadestudio.net/privacy#simply-pdf describes the Android app. Before the web version is public, add a paragraph to it in `srn-n/simply-made-studio` → `privacy.html` (and bump its "Last updated" date). Suggested text:

> **Simply PDF on the web.** The web version works the same way as the app: the files you open are processed in your browser on your device and are never uploaded. The site loads nothing from other servers, sets no cookies and uses no analytics. It keeps a copy of the app in your browser so it works offline, and stores your theme and (if you leave it on) the names and sizes of files you've made, in your browser only. Like any website, the site is served by a hosting provider (Vercel), whose servers briefly log standard request details such as IP address and browser type to deliver and secure the site; we don't use those logs to track you.

The last sentence is there because a hosted website, unlike the offline Android app, does reach a server when the page is fetched. Saying so keeps the "no guesswork" promise.

## Commands for Samiur

From `C:\Working Projects\SimplyPDFWeb`, after creating the empty GitHub repo (no README, licence or .gitignore, so the first push is clean):

```
git init -b main
git add -A
git commit -m "Simply PDF Web 1.0.0: first web release"
git remote add origin https://github.com/srn-n/simply-pdf-web.git
git push -u origin main
```

Then in Vercel: **Add New → Project → import the repo**. The framework is Vite, and `vercel.json` already sets the build and output. Leave Web Analytics and Speed Insights **off**, then Deploy. Once it's live, open Settings on the site and check it says 1.0.0.
